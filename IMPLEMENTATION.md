# FairCare — Implementation Documentation

A complete, ground-level account of how this project is built: every service, every
endpoint, every table, every frontend page and component, the data pipeline, the
container stack, the test suite, and the design decisions behind them.

The app helps people in India **estimate the cost of a medical treatment**, compare
that cost across cities, check **government health-scheme eligibility**, find
**hospitals** (government / empanelled options surfaced first), and get a rough
**diagnosis lead** from a symptom description — all on transparent, rule-based logic
over a PostgreSQL database, with an **optional multimodal layer** (photograph a
hospital bill, or speak instead of type) powered by Groq.

## 1. Guiding principles

**No cost figure or eligibility result is ever generated by an LLM.**
Every number returned by the API traces back to a row in Postgres, and every
fallback or approximation is explicitly labelled in the response — never silently
substituted.

The multimodal layer does not weaken this. When a user uploads a photo of a bill, a
Groq vision model performs OCR / structuring **only** (its prompt: "read ONLY what
is printed … do NOT estimate, guess, infer, or add any amount"). The "is this price
fair?" verdict and every comparison figure are then computed by our own rule-based
`cost_service`. The model never sees our cost data.

**Data honesty.** All seed cost figures are sample data, clearly labelled per row in
the `source` field: they are model-derived from a base-rate table, not scraped from
real invoices, and not verified CGHS / PM-JAY figures. National reference rates are
rounded approximations from secondary sources. The UI footer and per-estimate source
list repeat this.

**Clean degradation.** With no `GROQ_API_KEY` set, the multimodal features simply
hide and everything else keeps working: `/api/multimodal/status` reports everything
`false`, the POST routes return `503`, and the frontend never renders the bill-upload
button or the server-side voice fallback.

**Portability of the schema.** ORM models use SQLAlchemy's generic `JSON` type (not
Postgres `JSONB`/`ARRAY`), so the exact same model metadata builds an in-memory
SQLite database for the unit tests and a Postgres database in production.

## 3. Architecture

```
┌────────────┐   HTTP    ┌──────────────────────────────────┐   SQL   ┌────────────┐
│  Next.js   │ ────────▶ │            FastAPI               │ ──────▶ │ PostgreSQL │
│  frontend  │           │  routers → services → db.repos  │         │    16      │
│ (App Rtr)  │ ◀──────── │        (SQLAlchemy 2, sync)      │ ◀────── │            │
└────────────┘  JSON     │                                  │         └────────────┘
      │                  │  services/multimodal ──▶ Groq API (vision + Whisper)
      │ SSR fetch        └──────────────────────────────────┘
      ▼
 API_INTERNAL_BASE_URL (http://backend:8000 inside compose)
```

**Request flow (cost estimate example):**

1. Browser `POST /api/predict-cost` with `{treatment_id, city|state, hospital_type?, lang?}`.
2. `RequestIDMiddleware` assigns/accepts `X-Request-ID`, binds it + method + path
   to the structlog context.
3. CORS middleware validates `Origin` against `settings.backend_cors_origins`.
4. `routers/predict.py` resolves the treatment via `treatment_service.get_treatment_by_id`,
   validates that a location was supplied, clamps `lang` to `en|hi`.
5. `cost_service.estimate_cost(db, …)` runs the five-tier lookup against rows
   pulled by `db/repositories.py`.
6. The router assembles a `PredictCostResponse` (treatment + estimate + factors +
   source rows + disclaimer) and returns it.
7. Middleware logs one `request` line with `status_code` and `elapsed_ms`, echoes
   `X-Request-ID` on the response.

**Sync all the way down.** SQLAlchemy 2.0 is used in **sync** mode with `psycopg`
v3. FastAPI runs the sync route handlers in a threadpool. The service functions take
a `Session` as their first argument; the query layer (`db/repositories.py`) returns
plain dicts / nested dicts in the same shape a former file-based `data_loader`
produced, which is why the scoring code in the services is essentially unchanged
from the pre-database version.

**Schema ownership.** Alembic owns the schema. The backend container's
`entrypoint.sh` runs `alembic upgrade head`, then `python -m app.seed`, then starts
Uvicorn. Seed fixtures live in git as the human-editable source of truth.

## 4. Technology choices

| Layer | Choice | Why |
|---|---|---|
| Web framework | FastAPI + Uvicorn | Pydantic-native validation, automatic OpenAPI docs at `/docs` & `/redoc`, sync handlers in a threadpool |
| Validation | Pydantic v2 | Request/response models double as the API contract and the OpenAPI schema |
| Config | `pydantic-settings` | One typed `Settings` object; `.env` support; the only place `os.environ` is read |
| DB | PostgreSQL 16 | Real relational store; JSON columns for list/dict fields |
| ORM | SQLAlchemy 2.0 (sync) + `psycopg` v3 | Modern typed `Mapped[...]` models; `pool_pre_ping` to survive idle-dropped connections |
| Migrations | Alembic | `env.py` imports the app's `Base.metadata` and `settings.database_url`; `alembic check` in CI keeps models and migrations in sync |
| Multimodal | Groq API (OpenAI-compatible) | `chat/completions` with an image for OCR, `audio/transcriptions` (Whisper) for voice; one `httpx` wrapper |
| HTTP client | `httpx` | Used for the Groq calls; 45 s timeout, one retry on 5xx |
| Logging | `structlog` | One JSON object per line to stdout; request-id bound per request |
| Rate limiting | `slowapi` | In-memory token bucket; tighter limits on `/api/auth/*` and `/api/multimodal/*` |
| Uploads | `python-multipart` | Multipart parsing for bill photos / audio clips |
| Frontend | Next.js 16 (App Router, Turbopack), React 19, TypeScript | Server components for data-heavy pages (SSR), client components for interactive forms |
| Styling | Tailwind CSS 3 | Custom "rate-card" token set; no component library |
| Auth | stdlib `hashlib.pbkdf2_hmac` + DB sessions | No external auth provider; 200k-iteration PBKDF2-HMAC-SHA256, per-user 16-byte salt |
| Maps | OpenStreetMap embed `<iframe>` | No API key, no JS SDK, no tracker |
| Tests | pytest + `respx` | In-memory SQLite fixture DB; Groq HTTP mocked |
| Lint | `ruff` (`E,F,I,UP,B`) | line-length 100; `E501` and `B008` (FastAPI `Depends()` default) ignored |
| Container | Docker + docker-compose | 3 services; non-root users; healthchecks |

## 5. Configuration system

All configuration is environment-driven and read exactly once, in
`backend/app/config.py`, into a `Settings` object imported everywhere else as
`settings`. **No other module reads `os.environ`** (except `rate_limit.py`, which
reads the optional `RATE_LIMIT_STORAGE_URI` directly).

`Settings` is a `pydantic_settings.BaseSettings` with `env_file=".env"`,
`extra="ignore"`, `case_sensitive=False`. `get_settings()` is `@lru_cache`d.

| Variable | Default | Notes |
|---|---|---|
| `APP_ENV` | `development` | `production` stops `forgot-password` returning the reset token in the body |
| `APP_VERSION` | `0.2.0` | Reported by `/api/health` and set as the FastAPI `version` |
| `LOG_LEVEL` | `INFO` | Passed to `structlog.make_filtering_bound_logger` |
| `DATABASE_URL` | `postgresql+psycopg://faircare:faircare@localhost:5432/faircare` | SQLAlchemy URL; `sqlite`-prefixed values switch the engine kwargs (see §9) |
| `BACKEND_CORS_ORIGINS` | `localhost:3000`, `127.0.0.1:3000`, `[::1]:3000` | Accepts a **JSON list** or a plain **comma-separated string** — a `field_validator(mode="before")` with `NoDecode` handles both |
| `SESSION_TTL_SECONDS` | `604800` (7 days) | `auth_sessions.expires_at` |
| `RESET_TOKEN_TTL_SECONDS` | `3600` (1 hour) | `password_reset_tokens.expires_at` |
| `PBKDF2_ITERATIONS` | `200000` | PBKDF2-HMAC-SHA256 rounds |
| `RATE_LIMIT_DEFAULT` | `120/minute` | Global slowapi default |
| `RATE_LIMIT_AUTH` | `20/minute` | Applied per-route on `/api/auth/*` |
| `RATE_LIMIT_MULTIMODAL` | `12/minute` | Applied per-route on `/api/multimodal/*` |

| `GROQ_BASE_URL` | `https://api.groq.com/openai/v1` | OpenAI-compatible base |
| `GROQ_VISION_MODEL` | `meta-llama/llama-4-scout-17b-16e-instruct` | Bill-photo OCR model |
| `GROQ_TRANSCRIBE_MODEL` | `whisper-large-v3-turbo` | Voice transcription model |

## 6. Backend application bootstrap

`app/main.py` builds the FastAPI app:

- **`configure_logging()`** is called at import time (see §7).
- **`lifespan`** async context manager logs a `startup` event with `env`, `version`,
  `db_ok` (a live `SELECT 1`), `groq_enabled`, and the CORS origins; logs `shutdown`
  on exit.
- **`_db_ok()`** opens a connection and runs `SELECT 1`; catches every exception,
  logs `db_healthcheck_failed`, returns `False`. Used by the three health routes and
  the startup log.
- **Middleware** (added in this order): `RequestIDMiddleware`, then `CORSMiddleware`
  with `allow_origins=settings.backend_cors_origins`, `allow_credentials=True`,
  `allow_methods=["*"]`, `allow_headers=["*"]`, `expose_headers=["X-Request-ID"]`.
- **`app.state.limiter = limiter`** wires the shared slowapi limiter.

**Exception handlers** (all attach `request_id` from `request.state`):

| Exception | Status | Body |
|---|---|---|
| `RateLimitExceeded` | 429 | `{"detail": "Rate limit exceeded: …", "request_id"}` |
| `RequestValidationError` | 422 | `{"detail": <pydantic error list>, "request_id"}` |
| `StarletteHTTPException` | passthrough | `{"detail": exc.detail, "request_id"}` |
| `Exception` (catch-all) | 500 | `{"detail": "Internal server error.", "request_id"}` — full traceback is logged via `log.exception`, never returned |

**Routers** included: `treatments`, `predict`, `hospitals`, `schemes`, `auth`,
`multimodal`.

**Health / meta routes:**

| Route | Behaviour |
|---|---|
| `GET /` | `{"service", "docs": "/docs", "health": "/api/health"}` |
| `GET /api/health` | `{"status": "ok"|"degraded", "db": "ok"|"down", "version", "groq_enabled"}` |
| `GET /api/health/live` | static `{"status": "ok"}` (liveness) |
| `GET /api/health/ready` | `{"status": "ok"}` or **503** `{"status": "not-ready", "db": "down"}` — used by the container `HEALTHCHECK` |

Interactive docs: `/docs` (Swagger) and `/redoc`.

## 7. Logging and request IDs

`app/logging_config.py` configures `structlog` once (guarded by a module flag):

- Shared processors: `merge_contextvars`, `add_log_level`, ISO-8601 UTC timestamp.
- Rendered by `structlog.processors.JSONRenderer()` → **one JSON object per line**
  on stdout.
- The stdlib root logger is cleared and pointed at a single stdout `StreamHandler`
  with the structlog `ProcessorFormatter`, so third-party log records are rendered
  the same way.
- `uvicorn.access` handlers are cleared and `propagate = False` — Uvicorn's access
  log is suppressed because `RequestIDMiddleware` already emits an equivalent line.

`app/middleware.py` — `RequestIDMiddleware` (Starlette `BaseHTTPMiddleware`):

1. Reads `X-Request-ID` from the request or generates `uuid4().hex`.
2. Stores it on `request.state.request_id`.
3. `structlog.contextvars.clear_contextvars()` then `bind_contextvars(request_id,
   method, path)` — every log line emitted during the request carries these.
4. Times the request with `time.perf_counter()`.
5. On success: sets `X-Request-ID` on the response, logs `request` with
   `status_code` and `elapsed_ms`.
6. On exception: logs `request_failed` with `elapsed_ms` and re-raises (the
   catch-all handler in `main.py` then produces the 500).

## 8. Rate limiting

`app/rate_limit.py` exposes a single shared `slowapi.Limiter`:

- `key_func=get_remote_address` (client IP).
- `default_limits=[settings.rate_limit_default]` (`120/minute`).
- `storage_uri=os.getenv("RATE_LIMIT_STORAGE_URI", "memory://")` — **in-memory by
  default**; set to a Redis URI for multi-worker deployments so the limit is shared
  across processes.
- `headers_enabled=False` — slowapi's per-route header injection needs the handler
  to return a Starlette `Response`, but the handlers return dicts / Pydantic models.
  The 429 enforcement itself works regardless.

Per-route tighter limits are applied with the decorator, e.g. in `routers/auth.py`:

```python
@router.post("/login", response_model=AuthResponse)
@limiter.limit(settings.rate_limit_auth)          # 20/minute
def login(request: Request, payload: LoginRequest, db: Session = Depends(get_db)):
    ...
```

`request: Request` must be a parameter for slowapi to find the client address.
`routers/multimodal.py` applies `settings.rate_limit_multimodal` (`12/minute`) the
same way. A 429 returns `{"detail", "request_id"}` via the `RateLimitExceeded`
handler.

## 9. Database layer

### 9.1 Engine and session (`app/db/session.py`)

```python
_engine_kwargs = {"pool_pre_ping": True, "future": True}
if settings.database_url.startswith("sqlite"):
    _engine_kwargs = {"future": True, "connect_args": {"check_same_thread": False}}
engine = create_engine(settings.database_url, **_engine_kwargs)
SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False, future=True)
```

- `pool_pre_ping=True` transparently recycles connections dropped by Postgres or a
  proxy between requests (the usual cause of a first-request-after-idle 500).
- SQLite (unit tests) uses `check_same_thread=False` and ignores the pool kwargs.
- **`get_db()`** is the FastAPI dependency — yields a request-scoped `Session` and
  always closes it in a `finally`.

### 9.2 Declarative base (`app/db/base.py`)

A one-line `class Base(DeclarativeBase)` shared by every model and by Alembic's
autogenerate / `alembic check`.

### 9.3 ORM models (`app/db/models.py`)

Column names deliberately mirror the original seed-JSON keys. **Portable types
only** — `JSON` (not `JSONB`/`ARRAY`), `String`, `Text`, `Float`, `Integer`,
`DateTime(timezone=True)` — so one `Base.metadata` builds both the SQLite test
schema and the Postgres production schema.

## 11. Seed data and generators

### 11.1 The seed loader (`app/seed.py`)

```
python -m app.seed            # upsert every fixture by primary key (idempotent)
python -m app.seed --fresh    # DELETE the 5 reference tables first, then upsert
```

- `_upsert(db, model, rows, pk="id")` — `db.get(model, row[pk])`; if missing,
  `db.add(model(**row))`; otherwise `setattr` each field.
- Parent-before-child ordering with an explicit `db.flush()`: **treatments** →
  `flush` → **cost_records** → **national_references** → **hospitals** → **schemes**.
- `_national_reference_rows()` reads the nested `national_reference.json`, drops the
  `_read_me` key, and flattens `{tid: {htype: entry}}` into rows with
  `id = f"natref_{tid}_{htype}"`.
- **User / session / bill-analysis tables are never touched by the seeder.**
- On any exception the transaction is rolled back and re-raised.
- On success it logs `seed_complete` with per-table counts and prints a summary.

### 11.2 The cost-records generator (`scripts/generate_seed_costs.py`)

A **developer tool**, not part of the running app. It deterministically expands a
compact base-rate table into `app/data/seed/cost_records.json` so the seed set is
realistic *and* byte-reproducible.

```
cd backend && python -m scripts.generate_seed_costs   # rewrites cost_records.json
```

Inputs (all in the script):

- `CITIES` — 7 cities → `(state, cost multiplier vs Delhi=1.00)`:
  Delhi 1.00, Mumbai 1.15, Bengaluru 1.05, Pune 0.95, Chennai 0.95, Hyderabad 0.90,
  Kolkata 0.85.
- `TYPE_MULT` — `govt 1.0`, `private_low 2.3`, `private_mid 3.6`, `private_high 5.0`.
- `BASE` — 27 treatment ids → `(govt-baseline avg INR, [hospital types], [cities])`.
- `SAMPLE_RANGES` — per-type `sample_size` bounds.
- `SOURCE` — the honesty string stamped on every row.

Per (treatment × city × type):

```
jitter   = 0.9 + 0.2 * rand(tid, city, htype)          # ±10 %, seeded
avg      = base_avg * TYPE_MULT[htype] * city_mult * jitter
cost_min = avg * (0.70 + 0.06 * rand("min", …))
cost_max = avg * (1.28 + 0.14 * rand("max", …))
sample   = int(lo + (hi - lo) * rand("n", …))
data_year = 2026 | 2025 | 2024   (by a seeded roll; private_high can be 2023)
```

`rand(*parts)` is `int(sha256("::".join(parts))[:12], 16) / 0xFFFFFFFFFFFF` — a
stable hash-based pseudo-random in `[0, 1)`, so re-running yields identical output.
Costs are rounded to the nearest ₹100. Result: **526 rows across 27 treatments**.

## 12. Cost estimation service

`app/services/cost_service.py` — `estimate_cost(db, treatment_id, city=None,
state=None, hospital_type=None, lang="en") -> dict`.

Pulls `repositories.all_cost_records(db)` and `repositories.national_reference_map(db)`
once, filters to `by_treatment`, and tries progressively broader tiers. **Every
response discloses which tier produced the number** via `is_fallback` +
`fallback_reason` (bilingual).

### 12.1 The five tiers

| Tier | Condition | `is_fallback` | Reason builder |
|---|---|---|---|
| **1 — Exact city + hospital type** | `city` given, rows match both city and `hospital_type` | `False` | — |
| **2 — Exact city, any type** | `city` given, rows match city but not the type (or no type asked) | `True` | `_reason_city_any_type` |
| **3 — State-wide pool** | `state` given, or derived from a `city` that has data; rows match the state (optionally further filtered by type if that subset is non-empty) | `True` | `_reason_state` |
| **4 — National reference rate** | `national_references` has an entry for the treatment (cited PM-JAY/CGHS figure; picks the `hospital_type` entry or falls back to `govt`) | `True` | `_reason_national_ref` |
| **5 — National pooled sample average** | any rows exist for the treatment at all | `True` | `_reason_national_pool` |

If `by_treatment` is empty **and** there is no national reference → returns
`estimate: None` with a "No verified cost data exists for this treatment yet."
reason; the router turns that into a **404**. A final `estimate: None` also results
if none of the tiers match ("No data available for this location/treatment
combination.").

Tier 4 rationale (from the code comment): PM-JAY / CGHS package rates are the same
nationwide, so one `govt` entry per treatment correctly covers all 36 states/UTs —
it is deliberately **not** pooled sample data and only exists for treatments where
real research found a verifiable figure.

### 12.2 Pooling (`_weighted_estimate`)

Given the matched rows:

```
cost_min = min(row.cost_min)
cost_max = max(row.cost_max)
cost_avg = Σ(row.cost_avg * row.sample_size) / Σ(row.sample_size)     # sample-weighted
avg_year = Σ(row.data_year * row.sample_size) / Σ(row.sample_size)    # sample-weighted
score    = 0.6 * size_score(Σ sample_size) + 0.4 * recency_score(round(avg_year))
```

All money values are rounded to 2 dp.

### 12.3 Confidence

```
size_score(n)    = min(n / 100, 1.0)
recency_score(y): age 0 → 1.0 | 1 → 0.85 | 2 → 0.70 | 3 → 0.55 | ≥4 → 0.40   (age = CURRENT_YEAR - y, floored at 0)
label(score):    ≥ 0.75 → "high" | ≥ 0.45 → "medium" | else "low"
```

Returned as `confidence_score` (0–1, 2 dp) and `confidence_label`.

### 12.4 Factors (`_build_factors`, bilingual)

Up to three plain-language `{label, detail}` entries:

1. **Hospital type** — only when the matched rows contain *both* `govt` and non-govt
   rows: "Private hospitals in this data run about *N*% higher than government
   hospitals for the same procedure." (`N = round((priv_avg − govt_avg) / govt_avg *
   100)`).
2. **Location** — either "Estimate is based on records tagged to *label*." (exact
   match) or "Exact location match wasn't available, so a broader pool was used — see
   the note above." (fallback), or "This is a national rate/average, not specific to
   any one city or state." (no location label).
3. **Data volume** — "Built from *T* pooled records across *R* verified data row(s)."

Hindi variants of every string are produced when `lang == "hi"`.

### 12.5 Router (`routers/predict.py`)

- 404 if `treatment_id` is unknown.
- **400** if neither `city` nor `state` is provided ("Provide at least a city or a
  state/UT.").
- `lang` clamped to `en|hi` (anything else → `en`).
- 404 if `estimate_cost` returns `estimate: None`.
- Success → `PredictCostResponse` with the treatment, echoed location + type, the
  estimate, factors, the matched source rows (`sources`), and a fixed bilingual
  `disclaimer` constant.

## 13. Treatment / symptom search service

`app/services/treatment_service.py` — `search_treatments(db, query, strict=False)`.
Empty query → all treatments. Otherwise: lower-case the query, strip stopwords,
score every treatment, sort descending, apply a threshold.

**Two scoring functions, deliberately kept separate** so tuning one never regresses
the other:

### 13.1 Lenient (`strict=False`) — plain treatment-name search

Candidates: `name` + `aliases` (+ `name_hi`). Score for a candidate:

- **Substring bonus**: if the raw query contains the candidate or vice versa →
  `0.7 + 0.3 * (shorter_len / longer_len)`.
- Otherwise a blend:
  `0.4 * jaccard(query_words, candidate_words) + 0.4 * avg_per_word_best_SequenceMatcher_ratio + 0.2 * SequenceMatcher(sorted query, candidate)`.

Threshold `MIN_USEFUL_SCORE = 0.32`. Returns the top **8** above threshold; if none
clear it, returns up to **5** closest with score `> 0` (typo/voice tolerance — a
wrong treatment-*name* guess is low-stakes because the user already knows what they
need).

### 13.2 Strict (`strict=True`) — symptom checker only

Candidates additionally include the treatment's `symptoms[]`. Score is an
**F1-style precision/recall blend over exact (post-stopword) word matches**, with a
small allowance for typo-level fuzzy matches:

```
for each query word:
    hit += 1.0                          if it is exactly in the candidate words
    hit += best_ratio                   if best SequenceMatcher ratio ≥ 0.82 (typo-level only)
precision = hits / len(query_words)
recall    = hits / len(candidate_words)
score     = 2·p·r / (p + r)             (0 if p + r == 0)
```

Threshold `MIN_USEFUL_SCORE_STRICT = 0.35`. Returns the top **5** above threshold
and **nothing** otherwise — an empty result correctly means "see a doctor", not a
failure. (Calibrated empirically: false-positive queries like "nausea and diarrhea"
score 0.0 against unrelated treatments; genuine loose matches score 0.28+.)

### 13.3 Stopwords

A ~60-word set of generic filler ("i", "my", "have", "pain", "cost", "surgery",
"operation", "hospital", "doctor", …) is stripped before scoring so a shared filler
word can't out-rank a shared anatomical term. `_strip_stopwords` refuses to strip a
query down to nothing (returns the original set in that case).

### 13.4 Router (`routers/treatments.py`)

- `GET /api/treatments/search?q=` → `search_treatments(db, q)` (lenient).
- `GET /api/treatments/search-symptoms?q=` → `search_treatments(db, q, strict=True)`.

Both return `list[Treatment]`.

## 14. Hospital service

`app/services/hospital_service.py` — `find_hospitals(db, treatment_id, city=None,
hospital_type=None, budget_mode=False)`.

1. Filter `all_hospitals` to those whose `treatments_offered` contains
   `treatment_id`; then optionally by `city` (case-insensitive) and exact `type`.
2. **Enrich** each hospital with a `cost_avg` / `cost_source` by finding the one
   `cost_record` matching `(treatment_id, hospital.city, hospital.type)` — `None` if
   there isn't one.
3. **Rank:**
   - Default (`budget_mode=False`): by `TYPE_RANK` (`govt 0 < private_low 1 <
     private_mid 2 < private_high 3`), then by `-basic_rating` — government and
     mission-aligned options first.
   - `budget_mode=True`: by `cost_avg` ascending (`None` sorts last as `+inf`), then
     `TYPE_RANK` as a tie-break — pure cheapest-first.

`get_hospital_by_id(db, id)` returns the raw hospital dict (no cost enrichment).

**Router (`routers/hospitals.py`):**

- `GET /api/hospitals?treatment_id=&city=&type=&budget_mode=` — `treatment_id` is
  **required** (422 if missing); `type` is the query alias for `hospital_type`.
- `GET /api/hospitals/{id}` — 404 if not found; returns `HospitalOut` with
  `cost_avg=None, cost_source=None`.

## 16. Auth service

`app/services/auth_service.py` — accounts, server-side sessions, and password-reset
tokens, all Postgres rows now. **stdlib crypto only** — no external dependency.

### 16.1 Password hashing

```python
hash_password(password, salt_hex=None):
    salt_hex = salt_hex or secrets.token_hex(16)                 # 16 random bytes
    digest = hashlib.pbkdf2_hmac("sha256", password.encode(),
                                 bytes.fromhex(salt_hex),
                                 settings.pbkdf2_iterations)      # 200_000
    return digest.hex(), salt_hex
```

Verification re-hashes with the stored salt and compares with
`secrets.compare_digest` (constant-time).

### 16.2 Sessions and tokens

| Function | Behaviour |
|---|---|
| `create_user(db, name, email, password)` | lower-cases + trims email; raises `ValueError` if the email exists; stores `id = secrets.token_hex(8)`, hash, salt; returns the public `{id, name, email}` |
| `authenticate_user(db, email, password)` | returns the public user dict or `None` |
| `create_session(db, email)` | `token = secrets.token_urlsafe(32)`; `expires_at = now + SESSION_TTL_SECONDS` (7 days); returns the token |
| `get_user_by_session(db, token)` | `None` if the session is missing or expired (`_aware()` normalises SQLite's naive datetimes before comparing) |
| `delete_session(db, token)` | deletes the row if present (logout) |
| `create_reset_token(db, email)` | `None` if no account (caller decides whether to reveal); else `token = secrets.token_urlsafe(24)`, `expires_at = now + RESET_TOKEN_TTL_SECONDS` (1 hour) |
| `reset_password(db, token, new_password)` | `False` if the token is missing/expired or the user vanished; else re-hashes the password, deletes the token, commits, returns `True` |

## 17. Multimodal layer (Groq)

Directory `app/services/multimodal/`. Every entry point degrades cleanly when
`settings.groq_enabled` is `False`.

### 17.1 Groq client (`groq_client.py`)

A thin `httpx` wrapper over Groq's OpenAI-compatible REST API. **Nothing here
computes or reasons about money.**

- `_require_key()` raises `GroqUnavailable` (a `RuntimeError` subclass) when the key
  is missing.
- `_client()` → `httpx.Client(base_url=GROQ_BASE_URL, timeout=GROQ_TIMEOUT_SECONDS,
  headers={"Authorization": "Bearer …"})`.
- **`chat_vision(prompt, image_data_uri, model=None, force_json=True)`** — POSTs
  `/chat/completions` with a single user message containing a `text` part and an
  `image_url` part (a `data:` URI), `temperature=0`, `max_tokens=1500`, and
  `response_format={"type": "json_object"}` when `force_json`. **One retry** if the
  first response is `≥ 500`. Returns `choices[0].message.content` (raw string).
  Any `httpx.HTTPError` → `GroqUnavailable`.
- **`transcribe(file_bytes, filename, content_type, language=None, model=None)`** —
  POSTs multipart to `/audio/transcriptions` with `response_format="json"` and the
  `language` field when it is `en|hi`. One retry on `≥ 500`. Returns
  `{"text": <stripped>, "language": <detected>}`.
- **`parse_json_block(raw)`** — best-effort parse: strips ```` ``` ```` / `json`
  fences, then `json.loads`; on failure tries the substring between the first `{`
  and last `}`. Raises `GroqUnavailable("Model did not return valid JSON.")`.

### 17.2 Bill analysis (`bill_analysis.py`)

Pipeline for `analyze_bill(db, *, file_bytes, content_type, city=None,
treatment_id=None, lang="en")`:

1. **Local guards** (`_guard`, before any network call): `content_type` ∈
   `{image/jpeg, image/png, image/webp}`; size ≤ `MAX_UPLOAD_MB_IMAGE` (10 MB);
   non-empty. Failure → `UploadRejected` (a `ValueError`).
2. **Encode** the image as a base64 `data:` URI.
3. **Vision call** — `chat_vision` with `_VISION_PROMPT`: *"You are an OCR and
   document-structuring tool … Read ONLY what is printed … Do NOT estimate, guess,
   infer, or add any amount … Return a single JSON object with exactly these keys:
   `hospital_name`, `document_type` (bill|estimate|prescription|other),
   `detected_treatment`, `line_items[{description, amount}]`, `total_amount`,
   `currency`, `notes`."*
4. **Schema validation** — `ExtractedBill.model_validate(parse_json_block(raw))`.
   `ExtractedBill` / `ExtractedLineItem` coerce amount strings (strip `,`, `Rs.`,
   `₹`; `""`/`"null"` → `None`). Any `ValidationError`/`GroqUnavailable` → a friendly
   `GroqUnavailable("Could not read a structured bill out of that image. Try a
   clearer, straight-on photo.")`.
5. **Our code from here** (the model never sees any of it):
   - `effective_total()` = printed `total_amount`, or the sum of line-item amounts.
   - **Match a treatment**: if `treatment_id` was passed, use it; else fuzzy-match
     `extracted.detected_treatment` with `treatment_service.search_treatments(strict=
     False)` and take the top hit.
   - If a treatment matched and (`city` or `treatment_id`) is known, call
     `cost_service.estimate_cost(db, matched_id, city=city, hospital_type=None,
     lang=lang)`.
   - **Verdict** by comparing the bill total to **our** `cost_min` / `cost_max`:
     `below` (`< min`), `above` (`> max`), `within`, or `unknown` (no total / no
     estimate).
6. Returns `{extracted (dict), effective_total, matched_treatment, our_estimate
   (reuses the `Estimate` shape), verdict, disclaimer}`.

The `DISCLAIMER` string is explicit that the line items come from an OCR model and
the fair-range comparison uses our own sample data.

### 17.3 Transcription (`transcription.py`)

`transcribe_audio(*, file_bytes, filename, content_type, language="en")`:

- MIME allow-list: `audio/webm|ogg|mpeg|mp3|wav|x-wav|mp4|m4a|x-m4a`; size ≤
  `MAX_UPLOAD_MB_AUDIO` (25 MB); non-empty → else `UploadRejected`.
- Calls `groq_client.transcribe`; if `text` comes back empty → `GroqUnavailable
  ("Transcription came back empty.")`.
- Returns `{"text", "language"}`.

### 17.4 Endpoints (`routers/multimodal.py`) — rate-limited at `12/minute`

| Endpoint | Behaviour |
|---|---|
| `GET /api/multimodal/status` | `{vision, transcription, vision_model, transcription_model}` — all `false`/`null` when `groq_enabled` is false; otherwise both `true` with the configured model names |
| `POST /api/multimodal/analyze-bill` | multipart `file` + optional `city`, `treatment_id`, `lang` form fields. **503** if no key; reads the whole file into memory; **422** on `UploadRejected`; **503** on `GroqUnavailable` (model drift / upstream failure); else `BillAnalysisResponse` |
| `POST /api/multimodal/transcribe` | multipart `file` + `lang`. Same 503 / 422 / 503 mapping; else `TranscriptionResponse` |

`lang` is clamped to `en|hi` in both handlers. The uploaded bytes are processed in
memory and discarded — only the structured `bill_analyses` summary row concept
exists (the table is defined but the current handler returns the result without
persisting the image).

## 20. Frontend architecture

Next.js 16 App Router, React 19, TypeScript. Turbopack in dev; `output:
"standalone"` for a small Docker runtime image.

**Server vs client components:**

- **Server components** (default, `async`, run on the server per request):
  `app/layout.tsx`, `app/results/page.tsx`, `app/hospitals/page.tsx`,
  `app/hospitals/[id]/page.tsx`. They call `lib/api.ts` functions directly during
  SSR, read cookies via `next/headers`, and use the non-hook `t(lang, key)` form of
  i18n.
- **Client components** (`"use client"`): every interactive form and widget — the
  home page, compare, eligibility, symptom-checker, history, all auth pages, and all
  of `components/*`. They use the `useLanguage()` / `useAuth()` / `usePreferences()`
  hooks.

**`app/layout.tsx`** (server):

1. `await cookies()` → `initialLang` from `faircare_lang` (via `parseLang`), auth token
   from `faircare_auth_token`.
2. If a token exists, `await fetchMe(token)` server-side to hydrate `initialUser`
   (any failure → `null`, i.e. logged-out).
3. Renders `<html lang={initialLang}>`, preconnects + loads Google Fonts
   (Newsreader, Inter, IBM Plex Mono, Noto Sans Devanagari), wraps children in
   `<Providers initialLang initialUser>`, and a header/footer. The footer text is the
   `footer.note` data-honesty line.

## 21. Frontend API client

`lib/api.ts` — typed `fetch` wrappers. All GET calls use `cache: "no-store"`.

**Base URL resolution** (this file runs both in the browser and during SSR):

```
API_BASE =
  (typeof window === "undefined" ? process.env.API_INTERNAL_BASE_URL : undefined)  // SSR, server-only
  || process.env.NEXT_PUBLIC_API_BASE_URL                                          // browser, baked at build
  || "http://127.0.0.1:8000";                                                      // explicit IPv4 loopback
```

- Browser → `NEXT_PUBLIC_API_BASE_URL` (baked into the client bundle at build time;
  points at the host-published backend port). The default is the **IPv4** loopback,
  not `localhost`: on Windows, Node resolves `localhost` to IPv6 `::1` first while
  Uvicorn binds IPv4 only, which otherwise causes multi-second SSR timeouts.
- SSR → `API_INTERNAL_BASE_URL` when set. Inside docker-compose this is
  `http://backend:8000` (the compose network), because `localhost` there would be
  the frontend container itself.

**`handle<T>(res)`** — on `!res.ok`, reads `body.detail` for the error message; a
`404` with `detail === "Not Found"` (FastAPI's unmatched-route body) is turned into
a targeted "the running backend is likely out of date" message.

**Exports:** `searchTreatments`, `searchTreatmentsBySymptom`, `predictCost`,
`fetchHospitals`, `checkSchemeEligibility`, `fetchHospitalById`, `signup`, `login`,

## 23. Internationalisation

`lib/i18n.ts`:

- **`Lang`** = `"en" | "hi" | "ta" | "te" | "bn" | "mr" | "gu" | "kn"` — English,
  Hindi, Tamil, Telugu, Bengali, Marathi, Gujarati, Kannada.
- `LANGUAGE_LABELS` shows each language's **autonym** (its own script) in the
  dropdown.
- `parseLang(value)` returns a valid `Lang` or falls back to `"en"`.
- `HOSPITAL_TYPE_LABELS_I18N[lang][type]` — the four hospital-type labels in all 8
  languages; `hospitalTypeLabel(lang, type)` looks them up (falls back to English,
  then the raw key).
- **`dict`** — one object per translation key, each with a value for all 8 languages.
  Keys are grouped by area: `nav.*`, `footer.*`, `home.*`, `results.*`,
  `confidence.*`, `compare.*`, `eligibility.*`, `symptom.*`, `hospitals.*`,
  `hospitalDetail.*`, `hospitalCard.*`, `history.*`, `methodology.*`, `auth.*`,
  `priceCheck.*`, `voice.*`, `search.*`, `payment.*`, `insurance.*`, `costOfCare.*`,
  `share.*`, `readAloud.*`, `settings.*`, `disclaimer.*`.
- **`TranslationKey`** is `keyof typeof dict`, so a missing/typo'd key is a **compile
  error** (`tsc --noEmit` in CI catches it). `t(lang, key)` returns
  `dict[key][lang] ?? dict[key].en ?? key`.

Two entry points: the hook (`useLanguage().t(key)`) for client components and the
bare `t(lang, key)` for server components.

## 24. Routing and the auth gate

`frontend/proxy.ts` — in Next.js 16 the middleware file is named `proxy.ts` and
exports `proxy` (the rename of `middleware`). It runs on every request except
`_next/static`, `_next/image`, `favicon.ico` (the `config.matcher`).

Logic: if the path starts with `/login`, `/signup`, `/forgot-password`, or
`/reset-password` → allow. Otherwise, require the `faircare_auth_token` cookie; if
absent → `NextResponse.redirect("/login")`. (This is why an unauthenticated `curl /`
returns a 307 to `/login`.)

The `Header` component independently hides the nav/account controls on those four
auth routes and points the logo at `/login` there.

## 27. Voice input and bill-photo flows

### 27.1 Voice — two-tier, degrades to nothing

The mic button appears if **either** path is available:

1. **Primary — browser Web Speech API** (`window.SpeechRecognition` /
   `webkitSpeechRecognition`, i.e. Chrome/Edge/Safari). Runs fully on-device;
   `recognition.lang` is `hi-IN` or `en-IN`. Used directly in
   `TreatmentAutocomplete` and `symptom-checker`.
2. **Fallback — `lib/useServerTranscription.ts`** (Firefox, some Android webviews).
   A hook that:
   - Checks `window.MediaRecorder` + `navigator.mediaDevices.getUserMedia` exist,
     then `multimodalStatus()` — `available` is `true` only if **both** the browser
     supports recording **and** the backend has a Groq key.
   - `start(onTranscript, onError)` → `getUserMedia({audio:true})` → `MediaRecorder`
     → on stop, bundle the chunks into a `Blob` and `POST /api/multimodal/transcribe`
     → call `onTranscript(text)`.
   - Cleans up media tracks on stop and on unmount. Exposes `available`, `recording`,
     `busy`, `start`, `stop`.

If neither is available (no Web Speech, no Groq key) the mic button is simply not
rendered.

`TreatmentAutocomplete` treats voice as noisy: a spoken phrase is searched and
**auto-resolved to the top match**, showing "matched to *X*" rather than making the
user tap the dropdown. `symptom-checker` **appends** each transcript to the textarea
(symptoms accumulate).

### 27.2 Bill photo

Only in `PriceCheckTool`, only when `multimodalStatus().vision` is `true`. The
hidden `<input type="file" accept="image/jpeg,image/png,image/webp"
capture="environment">` (rear camera on mobile) → `analyzeBill(file, {city,
treatment_id, lang})` → the response's `effective_total` fills the quote field and
re-runs the local within/below/above check; `extracted.line_items` render in a card
with a note that an OCR model produced them and the fair-range uses our own data.

## 32. Security posture

**In place:**

- Passwords: PBKDF2-HMAC-SHA256, 200k iterations, per-user 16-byte random salt,
  constant-time comparison. No plaintext, no reversible storage.
- Sessions: opaque `secrets.token_urlsafe(32)` tokens, server-side rows, 7-day TTL,
  deleted on logout.
- Reset tokens: `secrets.token_urlsafe(24)`, 1-hour TTL, single-use (deleted on
  successful reset). In production the token is never returned in a response body,
  only logged as a stand-in for the email send.
- `forgot-password` returns an identical message for known and unknown emails
  (no account enumeration) — covered by a test.
- Rate limiting on all `/api/auth/*` (20/min) and `/api/multimodal/*` (12/min).
- CORS locked to configured origins; credentials allowed only for those origins.
- Request IDs on every response and every log line for traceability.
- The catch-all exception handler never leaks a traceback to the client.
- Upload guards (MIME allow-list + size cap) run **before** any Groq call.
- Bill images are held in memory and discarded — only a structured summary concept
  is kept; the vision prompt forbids inventing amounts and the reply is
  schema-validated before use.
- Frontend auth gate (`proxy.ts`) redirects unauthenticated users to `/login` for
  every non-auth route.
- `.gitignore` excludes real `.env` / `.env.local` files (only `*.example` are
  committed).

**Caveats / not yet done:**

- Rate-limit storage is in-memory — with `WEB_CONCURRENCY > 1` each worker has its
  own bucket. Point `RATE_LIMIT_STORAGE_URI` at Redis for a real multi-worker limit.
- No email delivery is wired up for password reset.
- No CSRF token — auth is bearer-token in a cookie set/read by JS; the API also
  accepts the token via the `Authorization` header.
- The auth token cookie is set from JS without `HttpOnly` / `Secure` / `SameSite`
  attributes (needed so the client can read it for the `Authorization` header and so
  SSR can read it from `next/headers`).
- **A Groq API key is committed in the repo-root `.env.example`.** Treat it as
  compromised: rotate it at the Groq console and replace the committed value with an
  empty placeholder (the file is meant to hold only placeholders). It also lives in
  git history, so history rewriting or key revocation is the only complete fix.

## 33. Known limitations and deliberate trade-offs

- **Sample cost data is placeholder** — model-derived from a base-rate table,
  labelled per row; replace with sourced CGHS / PM-JAY / state tariff data before
  real use.
- **National reference rates are secondary-source approximations** — rounded,
  gathered from aggregators referencing the NHA HBP schedule, not the primary
  `nha.gov.in` / `cghs.gov.in` PDFs.
- **Scheme eligibility is simplified** — real schemes use SECC / ration-card /
  occupational criteria, not flat income cutoffs; each scheme's `note` says so.
- **Multimodal needs a Groq key** — without it the bill-photo button and server
  voice fallback hide; browser Web Speech voice still works.
- **Bill images are processed in memory and discarded** — no image, no raw PHI blob
  is persisted.
- **Password-reset in development** returns the token in the API response (no mail
  service); in `APP_ENV=production` it is only logged.
- **History is local-only** — `localStorage`, not synced to an account or the
  backend, capped at 15 entries.
- **`GROQ_TEXT_MODEL`** is configured and passed through compose but not currently
  called by any service (reserved for a future text helper).
- Sync SQLAlchemy + threadpool is fine for this scale; a high-QPS deployment would
  want async drivers or more workers behind a shared rate-limit store.

**Roadmap** (from the README): real sourced rate lists + official empanelled-hospital
directory; a regression modelling layer once real `cost_records` volume justifies it
(with a schema-validated explanation layer that can only explain, never alter, a
number); gating the disclaimer behind an explicit acknowledgement; Redis-backed rate
limiting + sessions and deployment manifests.

**Add a government scheme**

  `max_annual_household_income`, `states_included`, `requires_govt_employment_or_pension`.
  `scheme_service` picks it up automatically. If you need a **new** rule type, add a

- Extend `Lang` / `LANGUAGES` / `LANGUAGE_LABELS` / `HOSPITAL_TYPE_LABELS_I18N` in
  `frontend/lib/i18n.ts` and fill the new language into **every** key in `dict`.

  `en` / `hi` strings for cost reasons/factors and disclaimers — extend
  `cost_service` and `routers/predict.py` if you need more server-side languages.

- New `app/routers/<name>.py` with an `APIRouter(prefix="/api/<name>")`; a service
  in `app/services/`; request/response models in `app/schemas.py`; `include_router`

**Change the schema**
- Edit `app/db/models.py`, then `python -m alembic revision --autogenerate -m "…"`,
  review the generated migration, `alembic upgrade head`. CI's `alembic check`

## 37. Episode / multi-treatment estimator

One combined estimate for a whole course of care. **No schema change.**

**Service** — `app/services/episode_service.py` — `estimate_episode(db, items, *, city,
state, hospital_type, lang, annual_household_income=None, is_govt_employee_or_pensioner=
False)` where `items = [{treatment_id, quantity}]`:

- Per item: `cost_service.estimate_cost(...)`, then multiply `cost_min/avg/max` by
  `quantity` into a line `{treatment, quantity, estimate, line_min, line_avg, line_max}`.
  Unknown treatments and items with no estimate go into `skipped[]` (with a reason) and
  are **excluded from the totals**.
- `totals` = summed line ranges; `confidence_label` = the **weakest** included line's
  label (honest worst-case). Empty → `"low"`.
- If income or the govt flag is supplied: `scheme_service.check_eligibility(...)`; the
  `eligible` schemes are surfaced as `{scheme_id, name, coverage_details}`. **No
  fabricated "covered amount"** — the seed schemes carry no per-procedure caps, so
  coverage stays qualitative (§1).
- Returns `{lines, skipped, totals, eligible_schemes, disclaimer}` (bilingual disclaimer).

**Router** — `app/routers/episode.py` — `POST /api/estimate-episode`; `EpisodeRequest`
constrains `items` to 1–12, `quantity` to 1–50; 400 if no items or no location (mirrors
`routers/predict.py`).

**Frontend** — `app/episode/page.tsx` (client): repeatable `TreatmentAutocomplete` +
quantity rows (add/remove), city/state/type selects reusing the home-page pattern,
optional household income + govt-employee inputs, a results table (per-line + a total
row), a `skipped` panel, an eligible-schemes list, `DisclaimerBanner`, and a
`window.print()` button with `print:hidden` chrome. A `FeatureCard` on `app/page.tsx`
links `/episode`.

**Tests** — `backend/tests/test_episode_service.py` (5): per-line multiples sum to the

## 38. Estimate explainer (Groq text model)

Puts the previously-unused `GROQ_TEXT_MODEL` (`llama-3.3-70b-versatile`) to work as a
**plain-language explainer of numbers our code already computed** — never a calculator.
Same trust model as §17.2: strict prompt + Pydantic schema, no numeric post-scrub, the
model never sees our cost tables.

**Groq client** — `groq_client.chat_text(*, prompt, model=None, force_json=True)`:
mirrors `chat_vision` (`temperature=0`, one retry on ≥500, `response_format=json_object`)
but text-only, defaulting to `settings.groq_text_model`.

**Service** — `app/services/multimodal/explain.py` — `explain_estimate(*, treatment_name,
location_label, hospital_type, our_estimate, line_items, factors, lang)`:

- `GroqUnavailable` when `not settings.groq_enabled`.
- The prompt hands the model **only** our `cost_min/avg/max`, `confidence_label`,
  `fallback_reason`, the `factors` text, the treatment/location/type, and any
  caller-supplied OCR `line_items` — with explicit rules: *do not invent, adjust, or
  recompute any rupee figure; no medical advice*.
- Returns JSON validated against `EstimateExplanation` (`summary`, `line_item_notes[]`
  `{item, note}`, `questions_to_ask[]`, `scheme_hint?`). Any `ValidationError` /
  `GroqUnavailable` → a friendly `GroqUnavailable`. The response carries a `disclaimer`
  string saying the wording is model-generated but the figures are ours.

**Router** — added to `app/routers/multimodal.py`:

- `POST /api/multimodal/explain-estimate` — `@limiter.limit(rate_limit_multimodal)`;
  503 if Groq is off; 404 unknown treatment / no estimate; 400 no location. **Server
