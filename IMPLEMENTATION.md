# Healthcare Cost Predictor — Implementation Documentation

How the project is built and how every feature works end to end, after the move
from flat JSON files to Postgres and the addition of a Groq-powered multimodal
layer.

---

## 1. What this project is

A web app for people in India to estimate the cost of a medical treatment,
compare it across cities, check government health-scheme eligibility, find
hospitals, and get a rough diagnosis lead from symptoms — on transparent,
rule-based logic over a real database.

**Guiding principle:** no cost figure or eligibility result is ever generated by
an LLM. Every number traces back to a Postgres row, and every fallback is
labelled in the API response. The multimodal layer keeps this intact — Groq does
OCR / transcription of *user-supplied* media only; the fair-price verdict and all
comparison numbers come from our own `cost_service`.

## 2. Architecture

```
┌────────────┐        ┌──────────────────────────┐        ┌────────────┐
│  Next.js   │  HTTP  │        FastAPI            │  SQL   │ PostgreSQL │
│  frontend  │ ─────▶ │  routers → services →    │ ─────▶ │            │
│ (App Rtr)  │        │  db.repositories (ORM)   │        │            │
└────────────┘        │                          │        └────────────┘
                      │  services/multimodal ──▶ Groq API (vision + Whisper)
                      └──────────────────────────┘
```

- **Sync** SQLAlchemy 2.0 + `psycopg` v3. FastAPI runs sync handlers in a
  threadpool; the service functions kept their original shape and only swapped
  their data source (`data_loader.py` → `db/repositories.py`).
- Alembic owns the schema. The backend container runs `alembic upgrade head`
  then `python -m app.seed` before Uvicorn starts.
- Seed fixtures (`app/data/seed/*.json`) stay in git as the editable source of
  truth; `app.seed` upserts them.

## 4. Database

### 4.1 Tables (`app/db/models.py`)

| Table | Key columns |
|---|---|
| `treatments` | `id` (str PK), name/name_hi, category/category_hi, `aliases` (JSON), `symptoms` (JSON), typical_duration, description |
| `cost_records` | `id` PK, `treatment_id` FK, city, state, hospital_type, cost_min/max/avg, sample_size, source, data_year — indexed on treatment_id / city / state / hospital_type |
| `national_references` | flattened from the nested seed JSON: `id` = `natref_<tid>_<type>`, treatment_id, hospital_type, cost_min/avg/max, sample_size, data_year, source |
| `hospitals` | `id` PK, name, type, city, state, lat, lng, contact, `treatments_offered` (JSON), `empanelled_schemes` (JSON), basic_rating, source |
| `schemes` | `id` PK, name, region_scope, `eligibility_rules` (JSON), coverage_details, `application_steps` (JSON), official_link, last_verified_at, note |
| `users` | `id` PK, name, `email` (unique), password_hash, password_salt, created_at |
| `auth_sessions` | `token` PK, email, expires_at |
| `password_reset_tokens` | `token` PK, email, expires_at |
| `bill_analyses` | `id` PK, created_at, user_id?, treatment_id?, city?, `extracted` (JSON), verdict, our_cost_avg? — **structured summary only, no image** |

Columns use SQLAlchemy's generic `JSON` (maps to `json` on Postgres, `JSON1` on
SQLite) so the same metadata builds the test DB and the production DB. `alembic
check` runs in CI to guarantee the migration and the models stay in sync.

### 4.2 Repositories (`app/db/repositories.py`)

Thin functions (`all_cost_records(db)`, `national_reference_map(db)`,
`all_hospitals(db)`, …) that run one query and return plain dicts / nested dicts
in the exact shape the old `data_loader.py` returned. This is why the scoring
code in the services is byte-for-byte the same except for the `db` parameter.

### 4.3 Seeding

`python -m app.seed` upserts every `app/data/seed/*.json` fixture by primary key
(`--fresh` deletes the five reference tables first). User / session /
bill-analysis tables are never touched by the seeder.

`cost_records.json` (526 rows across 27 treatments × up to 7 cities × 2–4
hospital types) is produced by `scripts/generate_seed_costs.py` — a compact
base-rate table expanded with published cost-of-living-style city multipliers,
per-hospital-type multipliers, and a seeded hash-based jitter, so re-running
gives byte-identical output. Every row's `source` states it is model-derived
sample data.

## 5. Cost estimation — five-tier fallback (unchanged logic)

`cost_service.estimate_cost(db, treatment_id, city?, state?, hospital_type?, lang)`
tries progressively broader tiers and always discloses which one produced the
number via `is_fallback` + a bilingual `fallback_reason`:

1. **Exact city + hospital type**
2. **Exact city, any hospital type** (pooled)
3. **State-wide pool** (given state, or the state derived from a city that has data)
4. **National reference rate** — a cited PM-JAY / CGHS package rate from
   `national_references`, only where a public figure exists; not pooled sample data
5. **National pooled sample average** — last resort, labelled as such

If nothing has data, the API returns 404 rather than fabricating a number.

Confidence (0–1, low/medium/high) is a weighted blend of pooled sample size
(`min(n/100, 1)`) and recency (full weight for current-year data, decaying to
0.4 at ≥4 years). `factors[]` explains the estimate in plain language
(govt-vs-private delta, location basis, data volume), bilingual.

## 6. Multimodal layer (Groq)

### 6.1 Client (`services/multimodal/groq_client.py`)

An `httpx` wrapper over Groq's OpenAI-compatible API
(`{GROQ_BASE_URL}/chat/completions` and `/audio/transcriptions`). 45 s timeout,
one retry on a 5xx, raises `GroqUnavailable` when the key is missing or the call
fails. Model IDs come from settings (`GROQ_VISION_MODEL`,
`GROQ_TRANSCRIBE_MODEL`) so a rotated model is a one-line env change.

### 6.2 Bill analysis (`services/multimodal/bill_analysis.py`)

1. **Local guards** — MIME in `{jpeg, png, webp}`, ≤ `MAX_UPLOAD_MB_IMAGE` (10),
   non-empty — before any network call.
2. **Vision call** — the image as a base64 data URI plus a strict prompt
   ("read ONLY what is printed … do NOT estimate, guess, or add any amount")
   with `response_format={"type":"json_object"}`.
3. **Schema validation** — the reply is parsed and validated against
   `ExtractedBill` (Pydantic, with amount-string coercion). Drift → `GroqUnavailable`
   ("could not read a structured bill … try a clearer photo").
4. **Our code from here** — fuzzy-match `detected_treatment` against our
   catalogue via `treatment_service.search_treatments`; if matched and a
   city / treatment is known, call `cost_service.estimate_cost` and set
   `verdict` ∈ {within, above, below, unknown} by comparing the bill total to
   **our** `cost_min` / `cost_max`. The model never sees our cost data.

Response: `BillAnalysisResponse` — `extracted`, `effective_total`,
`matched_treatment`, `our_estimate` (reuses the `Estimate` schema), `verdict`,
`disclaimer`.

### 6.3 Transcription (`services/multimodal/transcription.py`)

Audio MIME allow-list + ≤ `MAX_UPLOAD_MB_AUDIO` (25) guard, then
`groq_client.transcribe` (Whisper). Returns `{ text, language }`.

### 6.4 Endpoints (`routers/multimodal.py`, all rate-limited)

| Endpoint | Behaviour |
|---|---|
| `GET /api/multimodal/status` | `{ vision, transcription, vision_model, transcription_model }` — all `false`/`null` when no key |
| `POST /api/multimodal/analyze-bill` | multipart `file` + optional `city`, `treatment_id`, `lang`; `503` if no key, `422` on a bad upload, `503` on model drift |
| `POST /api/multimodal/transcribe` | multipart `file` + `lang`; same error mapping |

## 7. Production hardening

- **Config** — `pydantic-settings` `Settings` in `app/config.py`; loads
  `backend/.env`; the only place the environment is read.
- **Logging** — `structlog` renders one JSON object per line to stdout; the
  request-id and method/path are bound per request.
- **Request IDs** — `RequestIDMiddleware` accepts or generates `X-Request-ID`,
  binds it to the log context, echoes it on the response, and logs a
  `request` line with `status_code` + `elapsed_ms`.
- **Exception handlers** (`main.py`) — `RequestValidationError` → 422 with the
  error list + `request_id`; `HTTPException` passthrough with `request_id`;
  catch-all `Exception` → 500 `{detail: "Internal server error.", request_id}`
  with the full traceback logged, never leaked.
- **Health** — `/api/health` reports `db` ok/down + version + `groq_enabled`;
  `/api/health/live` is static; `/api/health/ready` returns 503 unless the DB
  answers `SELECT 1` (used by the container healthcheck).
- **Rate limiting** — `slowapi`, in-memory store, tighter limits on `/api/auth/*`
  (`RATE_LIMIT_AUTH`) and `/api/multimodal/*` (`RATE_LIMIT_MULTIMODAL`); a 429
  returns `{detail, request_id}`.
- **Auth** — users / sessions / reset tokens are DB rows now. PBKDF2-HMAC-SHA256,
  200k iterations, per-user 16-byte salt (stdlib only). `forgot-password` returns
  the token in the body only when `APP_ENV != production`; in production it is
  logged as a stand-in for the email send.

## 8. Frontend changes (UI intact)

No new pages, no layout / colour / spacing changes. New capability folds into
existing components with the existing Tailwind tokens.

- **`lib/api.ts`** — `multimodalStatus()`, `analyzeBill(file, {city, treatment_id, lang})`,
  `transcribeAudio(blob, lang)`; reuse the existing `handle<T>()` + `API_BASE`.
- **`lib/types.ts`** — `MultimodalStatus`, `TranscriptionResult`, `BillLineItem`,
  `ExtractedBill`, `BillVerdict`, `BillAnalysisResult`.
- **`lib/useServerTranscription.ts`** — `MediaRecorder` → `/transcribe` hook;
  `available` is gated on `multimodalStatus().transcription`, so it's inert
  without a key.
- **`components/PriceCheckTool.tsx`** — an extra "📷 Upload a bill photo" button
  next to the existing number input (shown only when `status.vision`). On upload
  it fills the existing quote field and renders the extracted line items in a
  card using the existing verdict styling. The manual-entry path is untouched.
- **`components/TreatmentAutocomplete.tsx`** — the existing mic button now also
  appears when only the server fallback is available; Web Speech stays primary,
  `useServerTranscription` is the fallback. No new visible control.
- **`app/symptom-checker/page.tsx`** — a small mic button on the textarea, same
  markup / classes as the autocomplete mic; Web Speech primary, server fallback.
- **`lib/i18n.ts`** — new keys (`priceCheck.uploadBill`, `voice.recording`, …)
  in all 8 languages; also filled in 4 pre-existing `settings.*` keys that
  `SettingsMenu` referenced but the dictionary was missing (they were failing
  `tsc`).
- **`next.config.js`** — `output: "standalone"` for a small Docker runtime image.

The typed API response shapes the frontend already depended on
(`PredictCostResponse`, `HospitalOut`, …) are unchanged, so the rest of the UI
renders exactly as before.

## 9. Ops

- **`docker-compose.yml`** — `db` (postgres:16-alpine, healthcheck, `pgdata`
  volume) → `backend` (waits for db healthy, migrates + seeds, then Uvicorn) →
  `frontend` (Next standalone). All config from the repo-root `.env`.
- **`backend/Dockerfile`** — `python:3.12-slim`, non-root, `entrypoint.sh` does
  migrate → seed → `uvicorn … --workers ${WEB_CONCURRENCY:-2}`.
- **`frontend/Dockerfile`** — `node:22-alpine` multi-stage (deps → build →
  runner copying `.next/standalone` + `.next/static` + `public`).
- **`Makefile`** — `up`, `down`, `logs`, `ps`, `psql`, `migrate`, `seed`,
  `revision`, `backend-test`, `lint`, `fmt`, `dev-backend`, `dev-frontend`.
- **`.github/workflows/ci.yml`** — backend job (ruff → `alembic upgrade head` →
  `alembic check` → `pytest --cov` against a Postgres service) and frontend job
  (`tsc --noEmit` → `next build`).
