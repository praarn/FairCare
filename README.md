# Healthcare Cost Predictor

A web app that helps people in India estimate the cost of a medical treatment, compare that cost across cities, check government health-scheme eligibility, find hospitals (with government/empanelled options surfaced first), and get a rough diagnosis lead from a symptom description — built on transparent, rule-based logic.

> **Current phase:** Phase 2 / MVP — rule-based, no ML/LLM yet. All seed cost figures are **placeholder sample data** (clearly labeled `"SAMPLE DATA"` in the `source` field of every record), not real CGHS/PM-JAY figures yet.

`Python` `FastAPI` `Pydantic v2` `Next.js 16` `React 19` `TypeScript` `Tailwind CSS`

---

## Design principle

**No cost figure or eligibility result is ever generated by an LLM.** Every number traces back to a JSON "database" (`backend/app/data/*.json`), and every fallback or approximation is explicitly labeled as such in the API response — never silently substituted.

---

## Features

- **Cost estimation** — five-tier fallback (exact city+hospital type → exact city → state pool → cited national reference rate → national sample average), each response labeled with exactly which tier produced it, plus a confidence score and plain-language explanatory factors
- **City comparison** — compare one treatment's cost across multiple cities in parallel, cheapest-first
- **Symptom checker** — strict F1-scored symptom-to-treatment matching that returns nothing rather than a weak guess, always paired with a medical disclaimer
- **Hospital finder** — filter by treatment/city/type, government-first ranking or pure "budget mode," government/empanelled status shown via a stamp badge, embedded OpenStreetMap location
- **Government scheme eligibility** — deterministic rule evaluation (income ceiling, state, government-employment/pension status) with a plain-language reason, coverage details, application steps, and official links
- **Accounts & history** — signup/login with PBKDF2-hashed passwords and server-side sessions; locally-saved estimate history for quick revisits without an account
- **8-language i18n** — English, Hindi, Tamil, Telugu, Bengali, Marathi, Gujarati, Kannada, with compile-time-checked translation keys
- **Methodology page** — a static, human-readable explanation of how cost tiers, confidence scoring, and eligibility rules work

## API reference

| Method | Path | Purpose |
|---|---|---|
| GET | `/` | Service welcome/info JSON |
| GET | `/api/health` | Health check |
| GET | `/api/treatments/search?q=` | Lenient fuzzy search by treatment name/alias (typo-tolerant, always returns closest matches) |
| GET | `/api/treatments/search-symptoms?q=` | Strict F1-scored search by symptom description (returns empty rather than a weak guess) |
| POST | `/api/predict-cost` | Tiered cost estimate for a treatment + location |
| GET | `/api/hospitals?treatment_id=&city=&type=&budget_mode=` | List hospitals offering a treatment, filterable and rankable |
| GET | `/api/hospitals/{id}` | Single hospital detail |
| GET | `/api/schemes/eligible?annual_household_income=&state=&is_govt_employee_or_pensioner=` | Rule-based scheme eligibility check |
| POST | `/api/auth/signup` | Create account, returns session token |
| POST | `/api/auth/login` | Authenticate, returns session token |
| POST | `/api/auth/logout` | Invalidate session token |
| GET | `/api/auth/me` | Current user from bearer token |
| POST | `/api/auth/forgot-password` | Issue a password-reset token |
| POST | `/api/auth/reset-password` | Consume reset token, set new password |

Interactive docs are available at `/docs` (Swagger UI) and `/redoc` once the backend is running.

## Data model (seed JSON files)

| File | Contents |
|---|---|
| `treatments.json` | Treatment catalog: id, name (+ Hindi), category (+ Hindi), aliases, symptoms, typical duration, description |
| `cost_records.json` | Sample cost rows: treatment × city × state × hospital type × min/max/avg cost × sample size × source × data year |
| `national_reference.json` | Cited PM-JAY/CGHS national package rates, for the subset of treatments where a real verifiable figure exists |
| `hospitals.json` | Hospital directory: id, name, type, city/state, lat/lng, contact, treatments offered, empanelled schemes, rating |
| `schemes.json` | Government scheme catalog: id, name, eligibility rules, coverage details, application steps, official link |
| `users.json`, `sessions.json`, `reset_tokens.json` | Runtime-created, gitignored — never shipped with seed data |

## Running the Project

Two servers must run at the same time, in **two separate terminals**:

- Backend (FastAPI) → `http://localhost:8000` (or `http://127.0.0.1:8000`)
- Frontend (Next.js) → `http://localhost:3000`

Start the backend first, then the frontend, in the exact order below for your OS.

### Windows (PowerShell / CMD)

**Terminal 1 — Backend**
```
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Terminal 2 — Frontend**
```
cd frontend
copy .env.local.example .env.local
npm install
npm run dev
```

### macOS

**Terminal 1 — Backend**
```
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Terminal 2 — Frontend**
```
cd frontend
cp .env.local.example .env.local
npm install
npm run dev
```

### Linux

**Terminal 1 — Backend**
```
cd backend
python3 -m venv venv
source venv/bin/activate
```

## Known limitations

- **No real database yet** — everything is flat JSON files; fine for an MVP, not for concurrent-write safety or scale
- **Sample cost data is placeholder**, not verified real-world figures
- **Password-reset email enumeration** — since no email service is configured, the reset endpoint returns the reset token directly in the API response when the account exists (`null` otherwise); acceptable for an MVP demo, would need a real email-sending step to fully close
- **No ML/LLM layer yet** — cost estimation and eligibility are 100% rule-based by design at this phase
- **History is local-only** — not synced to an account or backend, so it doesn't follow the user across devices

## Roadmap

1. **Data foundation** — real CGHS/PM-JAY rate lists and empanelled hospital directories, backed by Postgres/Supabase
2. **Modeling layer** — an XGBoost/LightGBM regression model once real `cost_records` volume justifies it, plus a Claude-based explanation layer with strict schema validation guaranteeing it can't introduce or alter any number
3. **Differentiators** — Budget Mode UI toggle (backend already supports `budget_mode=true`), a map view, voice input, EMI/loan info depth, further treatment-comparison enhancements
4. **Trust hardening** — gate the disclaimer behind an explicit "I understand" acknowledgment, and add a post-generation number-drift check once the Claude explanation layer exists
